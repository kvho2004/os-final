Discussion: Threads vs. Processes Comparison
After implementing both models, our team conducted a thorough comparison between the threaded and process-based approaches to evaluate their suitability for the "Symbiosis" scenario. The most immediate difference we encountered was the memory model; while threads naturally share a single address space and allowed us to directly access the SimState structure, the process-based version required us to explicitly map a shared memory region using mmap. This introduced a layer of complexity in the process version, as we had to ensure that every forked child could correctly reference the same physical memory addresses to track the animal counters.
In terms of synchronization, we found that the threaded implementation was significantly more elegant due to the use of POSIX condition variables. Being able to use pthread_cond_broadcast to instantly wake all waiting mice when the last cat left made the signaling logic intuitive and efficient. In contrast, the process version relied on named semaphores, which are more "heavyweight" and lack a native broadcast mechanism. To replicate the same behavior, we had to implement manual loops to signal waiting processes, which felt less responsive and added more boilerplate code to our animal lifecycles.
However, the process-based approach offered a major advantage in terms of fault isolation. Because each cat and mouse was an independent process, a crash or memory error in one would not necessarily terminate the entire simulation. While the threaded version is faster due to lower context-switching overhead, it is also more fragile; a single synchronization error can lead to a segmentation fault that brings down the whole "House." Despite this robustness, the overhead of managing persistent named semaphores and the additional IPC boilerplate made the process version more cumbersome to maintain.
Ultimately, we have chosen the Threaded Implementation as the best approach for the second part of the project. We found that the ability to use condition variables for complex signaling, specifically for the "Scatter" and "Last Cat" rules, provided a level of precision and performance that the process-based version couldn't match without significant workarounds. The direct access to shared state in the threaded model allowed us to focus more on the logic of the symbiosis itself rather than the mechanics of inter-process communication, making it the more scalable choice for future scenario expansions.
